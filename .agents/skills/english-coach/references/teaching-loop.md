# 教学微循环

在一个已冻结的可评分活动出现值得处理的问题时读取本文件。Review 使用 [review-protocol.md](review-protocol.md) 的短 repair，不展开这里的完整循环。

## 正交记录问题

一个回答可以有多个 `issues[]`。每项至少保存：

- `issue_id`、`issue_type`、`affected_criterion`；
- `focus_relation`、`impact`、`root_cause`；
- 可为空的 `recurrence_evidence_ids`；
- `nature: error | upgrade_opportunity`。

`upgrade_opportunity` 表示原表达正确，但存在有价值的精确度、搭配、语域或句式提升；它不能改变已经成功的 `task_result`。复发必须引用 error、active insight 或既有 evidence ID；没有结构化引用时只能记作本次新发现。

不影响理解、活动目标或迁移价值的偶发小错默认为 `incidental_slip`。它不进入完整循环，也不自动进入长期错误日志。

## 确定性仲裁

在同一次反馈判断中依次完成：

1. 保全完整、无提示的首次回答。
2. 合并同一根因造成的表面问题；一个问题即使命中多个标签也只处理一次。
3. 优先处理上游原因，不把它造成的下游症状重复计错。
4. 对仍独立的问题按以下顺序排序：
   1. 沟通阻断；
   2. 造成 essential 失败的根因；
   3. 改变或严重模糊意义；
   4. 命中冻结的活动标准；
   5. 命中当前焦点目标；
   6. 有结构化复发证据或高迁移价值；
   7. `upgrade_opportunity`；
   8. 偶发小错。
5. `partial` 先获得一次只补缺失部分的最小机会；完成后仍记实际支持，失败后再参与循环选择。
6. 两个独立核心失败意味着任务负荷或先修设计有问题：缩小任务或补一个先修，不并行展开两个全局循环。
7. 最终最多选择三个反馈主题，并记录选择或推迟原因；未选中的偶发小错忽略。

## 两段式反馈

第一段在首答后的同一条消息完成：

- 说明任务结果和焦点标准结果；
- 给出选中的一至三个问题；
- 提供必要的意义选项或最小解释；
- 对不进入完整循环的问题给一次可读完的简短反馈；
- 只要求学习者修复原表达或原任务中受影响的部分。

学习者完成原表达修复后，第二段才可单独给新 activity ID 的新题或新语境迁移。不要把修复与迁移同时塞进第一条消息。

原意含糊时先给有限的意图选项；选项仍不能覆盖真实意思时先澄清。澄清完成前不猜测意图并据此纠错。

## 循环预算

- 每课允许 `0–3` 个完整微循环；没有高价值问题时为零。
- 总复杂度预算为 `3`：
  - 局部语法、单个词或搭配、局部自然度、单一发音特征各为 `1`；
  - 核心理解、任务对齐、篇章组织、交际动作失败等全局问题各为 `2`。
- 每课最多一个全局循环。合法上限是三个局部循环，或一个全局加一个局部。
- 反馈主题总数同样不超过三个；三个主题都进入循环时不再附送其他小错。
- 准确度或纠错活动中的微循环属于主活动，但仍受预算、重试与课程总时长约束。

## 共同状态骨架

`独立探测 → 按冻结契约判定 → 归因、合并与排序 → 最少必要帮助 → 修复受影响功能 → 淡出帮助 → 新活动或新语境迁移 → 停止并记录`

Teach-back 只能检查规则或概念理解，不能代替词汇、语法、口语、写作或交际能力的实际迁移。“更高级”也不天然更好；升级服从原意、语境和当前目标。

## 七种 adapter

### 意义理解

定位文本或音频证据 → 对比可能解释 → 学习者用自己的话复述并指出依据 → 新短材料验证。

### 事实定位

明确待找的信息槽位 → 提取搜索锚点 → 定位对应句或音频片段 → 同类新材料寻找另一事实。

### 内容或篇章组织

找出缺失逻辑槽位 → 只给两三个关键词或结构框架 → 重组受影响内容 → 换题并撤去提纲。不要给完整范文替代首答。

### 语法形式

指出位置 → 诱导自我修正 → 必要时给最小规则或对比例 → 改变主语、时间或语境造新句。

### 词汇、搭配或语域

确认原意 → 区分语义错误、搭配问题和可选升级 → 最多比较两个候选表达 → 在个人化新语境中使用。

### 语用或互动

指出未实现的交际效果 → 给少量功能表达选择 → 重演关键回合 → 换场景完成同类交际动作。

### 发音可懂度

只有可靠音频时启用 → 一次只处理一个影响可懂度的特征 → 先感知或听示范 → 练词组 → 新短句验证。否则记 `not_assessable`。

## 帮助升级与停止

- 从不泄露答案的最小提示开始。同一问题最多两次递增帮助的重试。
- 两次后仍不会时，给完成当前理解所需的最小示范，再简化迁移；简化迁移仍失败时，记录缺失先修并结束。
- 保存实际使用过的最高 `support_level` 与全部相关 `support_kind`；最后答对不能把帮助重置为无。
- 节奏参考：局部语法或词汇约两三分钟；意义、事实、语用或发音约两至四分钟；组织约四至六分钟。硬边界仍是重试次数、复杂度预算和当次课程时间。
- 优先保护一次完整独立输出。时间不足以完成迁移时只记 `guided`，明确留待后续，不能伪造 `transfer` 或掌握结论。

## 纠错时机

- `probe / assessment`：先保全完整独立表现。只有技术故障、指令问题或真实沟通阻断可提前中止，此时为 `not_assessable`。
- `practice + accuracy`：每个独立小题结束后可以即时纠正。
- `fluency`：连续口语、复述、角色扮演或自由写作完整结束后统一反馈。
- `mixed`：先判断内容与任务完成，再处理语言形式。
- 独立且明确正确时直接前进。只有学习者明确不确定、答案明显可能来自猜测，或冻结契约要求迁移验证时，才追加辨析或新语境检查。

## 冻结结果

可见反馈生成时同时冻结首答判断、入选问题、选择理由、adapter、当前循环阶段、尝试次数、最高支持、model exposure、剩余预算和下一等待动作 `clarify | repair | transfer | advance`。可见反馈后再通过一次轻量 checkpoint 保存；恢复时继续该等待动作，不重问已完成内容。

## 主课修复的保存与恢复

主课沿用 `SaveActivityCheckpoint`，每轮先展示反馈，再保存一次；公共参数按 [tracker-actions.md](tracker-actions.md) 取最新回执。首次回答与后续回答共用原 `activity_id`。

1. **首答需要澄清或修复**：照常提交首答结果与选中问题，另给 `next_action=clarify|repair`、`feedback_text`、`followup_prompt`、`support_level` 和 `support_kind`；`stage_complete=false`。`followup_issue_ids` 可指定本次处理的已选问题，省略时覆盖全部选中问题；没有选中问题的补全使用活动 ID。
2. **等待回答**：展示返回的 `followup_state.followup_prompt`。收到回答后先反馈，再用新的幂等键保存 `activity_id,feedback_shown=true,answer_excerpt,followup_result,feedback_text,support_level,support_kind,next_action`。`followup_result` 为 `clarified|repaired|needs_help|stopped`；再次等待还需 `followup_prompt`。此时只提交后续变化，首答、评分标准结果、问题选择和 observation 保持冻结。
3. **继续或停止**：每个问题最多两次 repair 回答；澄清不计 repair，但每活动最多十二个后续回合。修好或明确停止后，按教学需要选择 `prepare_activity|show_transfer|show_summary|finalize_session`；只有该阶段已完成才给 `stage_complete=true`。时间不足时记录 `stopped`，不把辅助下修好算成独立掌握。
4. **新语境迁移**：`show_transfer` 要先调用 `PrepareActivity`，使用新的 activity ID 与完整契约；成功后才展示迁移题。它遵守既有活动数量和预算限制，不能把同题修复包装成新的独立首答。
5. **恢复与重试**：恢复时读取原契约、冻结首答与 `followup_state`，继续返回的等待动作。保存响应丢失时用原 key 和原 payload 重试；不重新判断首答，也不额外计一次修复。

`support_level=none|light_hint|heavy_hint|model`，程序保留最高帮助和累计 `support_kind`；`model_exposed` 一旦为真便保留。反馈摘要最多 1200 字符，题面与回答片段各最多 600 字符，帮助类型最多八种。后续记录只进入原活动的草稿，不追加独立 observation；课末在 session 保存首答结果、修复结果与帮助摘要。
