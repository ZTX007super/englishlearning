# 英语课堂响应提速实施方案

> 专项方案：原文件名为 `english-coach-latency-plan.md`。文内未加目录前缀的项目路径均以项目根目录为基准；当前阅读入口见 [项目 README](../../README.md)。

日期：2026-10-01  
状态：代码与协议已实施，隔离回归通过；真实课堂响应时间仍待实测，尚不宣称性能目标达标。

## 1. 目标与范围

减少英语课中的等待，使复习和主课能连续进行。优先处理开课、复习题之间、复习转主课三个位置。正式结课后的保存耗时不属于本次主要优化范围。

采用局部、中等规模的流程重构：提前备课，减少 AI 与 tracker 的串行往返，缩小每次调用内容，并同步简化教学文档。保留逐题复习、反馈先展示、逐题可靠存档的体验，不采用“多题只留在对话中，稍后再保存”的方案。

本次不重写整个项目，不以清除 V3 为前提，不调整学习目标、复习排程或评分标准，不引入常驻服务、新数据库或消息队列。

## 2. 已知耗时与测量边界

以下为用户提供的平均等待时间，均不包含新对话首次开始学习：

| 场景 | 当前平均值 |
| --- | ---: |
| 开课 | 45 秒 |
| Review 题间 | 40 秒 |
| Review 转主课 | 85 秒 |

新对话首次学习缺少已有上下文，耗时波动明显，偶尔超过 120 秒。这里的“首次”指新建对话后的首次学习，不是第一次使用项目，也不是第一次做某道题。

以上数据是体验基线，不是脚本性能测试。尚未取得样本数量、分布和各阶段精确起止点，不补造这些信息。后续统一测量口径，保留原始报告，不把新口径数据直接冒充严格可比结果。

此前只读检查中，一个 checkpoint 的内部计时为 263 毫秒，其他多个计时字段为零。该样本不能证明所有保存都很快；零值也不能证明对应操作没有耗时。

### 后续统一计时

| 指标 | 起点 | 终点 |
| --- | --- | --- |
| 开课等待 | 用户发出开始学习请求 | 首道完整可作答题目展示完毕 |
| 首次反馈等待 | 用户提交答案 | 首段有实质内容的反馈开始出现 |
| 题间总等待 | 用户提交当前答案 | 下一道完整可作答任务展示完毕 |
| 阶段切换等待 | 用户提交最后一个必要的复习回答或修复回答 | 主课首道完整可作答任务展示完毕 |

单独记录 AI/平台等待、工具往返、脚本内部耗时、调用次数和返回体大小。无法获得的指标标为未知，不用零代替。不计用户作答时间，不用“正在处理”之类提示充当反馈或首题。

新对话首次进入与已有上下文继续学习分组统计；普通正确回答与需要修复的回答分组统计。口语转写、联网故障等另作标注。

## 3. 当前流程中的候选瓶颈

这些是文档和代码中已识别的结构问题，具体耗时贡献仍需验证。

1. **现场准备主课活动。** `activity-preparation.md` 要求 AI 匹配难度配置、补齐契约、生成参数，再调用 `PrepareActivity`。活动蓝图可用不等于题目可直接展示。
2. **复习批次与逐题交互衔接不明确。** 复习协议按批保存，而课堂逐题进行；`StageReviewBatch` 的下一动作没有直接表达“继续当前批下一题”，容易产生额外解释和调用。
3. **复习转主课需要连续往返。** 保存复习后返回蓝图，AI 再准备活动，再调用脚本确认，才展示主课任务。
4. **重复生成和传输内容。** 保存复习时仍需提交题面、契约等本应已经冻结的内容；返回准备信息也可能带回暂时不需要的内容。
5. **教学规则跨文件分布。** 新对话需要加载更多规则；已有上下文中也可能重复读取或重新解释同一规则。

## 4. 目标流程

### 4.1 课前准备与开课

在上一课结束后的预加载或课包发布过程中，准备主课题面、判定标准、提示方案和必要变体。预准备必须遵守真实队首、材料权利和版本校验，不提前编造回答或实际支持程度。

实际开课仍要按当天状态选择到期复习、绑定 session 和活动编号、检查队首及材料有效性。到期内容不能在课前永久锁死。

拟增加一个组合入口，由程序按既有恢复优先级完成检查、必要启动和可确定的准备，最终返回当前一个可执行动作。动作名称在实现前确定，不假装现有接口已经支持。

程序内部仍保留检查和持久化边界；合并的是 AI 与工具之间的往返，不是取消校验。对未完成课程只恢复，不创建第二个 session。

缓存未命中时使用已校验、同队首的备用材料或给出明确阻塞；不得跳队列。仅将准备工作搬到开课脚本里现场执行，不算完成本项优化。

### 4.2 Review 内逐题进行

目标流程：

> 展示已冻结的当前题 → 用户作答 → AI立即展示必要反馈 → 一次轻量保存 → 返回并展示当前下一动作。

复习题批负责冻结项目、顺序、题型和容量；批次内增加明确的当前题位置与修复状态。逐题存档属于同一个预选批次，不能把每题重新抽取成新批，不能改变容量、顺序或原始评级。

下一动作可能是原题修复、最小示范后的重构、下一道复习题，或主课第一题。只有当前互动已经结束，才推进题位置。首次评级固定，提示后答对不能提高首次评级。

提前冻结题目与判定规则，只向用户展示当前题。正确回答默认简短反馈；错误按原短修复规则处理。保存后直接返回下一动作所需内容，不再通过额外 Bootstrap 或准备查询来寻找下一题。

如果反馈泄露后续题目标，应按现有协议将受影响项目标为 exposed 并延期；只有事先冻结且未暴露的备用项才可补位。

### 4.3 Review 转主课

目标流程：

> 最后一次复习反馈 → 保存复习并绑定、校验已备好的主课首活动 → 返回正式可展示题目。

尽量消除 AI 在保存返回后再次阅读蓝图、拼装契约和发起准备调用的过程。主课准备共享独立 `PrepareActivity` 的校验实现，避免两个入口逐渐产生不同标准。

如主课选择依赖复习结果，程序按明确规则选择预备变体，不预先假定学习者表现。无法确定的教学选择保留显式分支，不用猜测换取速度。

复习保存与主课准备需有可恢复的分阶段状态：复习已经存好而主课准备失败时，恢复准备步骤；不得重新出已答复习题，也不得重复追加复习结果。

### 4.4 缩小调用参数与返回

已冻结的题面、契约、稳定编号与版本信息由 tracker 保存并查找。AI提交题目编号、必要答案片段、首次判断和修复变化，不反复重写完整契约。

参数仍保留 session、版本、修订号等必要保护。程序验证题目确属当前批次、当前活动以及合法等待动作，不接受用编号绕过检查。

返回只含当前下一动作必需信息、回执和保护字段。不重复返回全批已答内容、无关历史或主课蓝图。即将展示新题时，必须提供完整判定所需的有界内容，不能为缩短返回而使 AI 在用户作答后补读标准。

### 4.5 简化日课文档

按“进入课程—复习—主课—反馈与存档—恢复”组织说明。每个动作写明输入、允许动作、成功标志与失败处理。

已在当前上下文完整加载且版本未变化的规则不重复读取；新对话仍需加载当前必需规则。适当把稳定的教学规则一次合并读取，减少逐文件往返；不把全量维护文档重新塞回入口。

排程算法、历史迁移和内部事务实现不进入普通教学必读路径。教学所需判定规则必须在出题前加载完毕。同步所有相关 reference，不能仅修改主 skill 留下相互冲突的旧规则。

## 6. 实施顺序

### 阶段 A：补足测量与明确契约

- 使用用户数据作为已有基线，不要求先重新上完整一课才开始改进。
- 补充能够自动收集的计时与往返计数，沿用现有日志或回执，不为计时单独增加课中工具调用。
- 在隔离测试数据上复现三个路径，确认依赖、返回大小及恢复行为。
- 明确题批、当前题、修复、保存、下一动作之间的状态表。

### 阶段 B：优先优化复习转主课

- 将主课契约的可确定部分提前编译，抽取共享绑定及校验逻辑。
- 实现保存复习后直接返回主课正式活动。
- 测试两个步骤之间中断及重试，确认复习不重复、主课不提前展示。

### 阶段 C：优化复习题间

- 为预冻结题批建立明确的位置和等待动作。
- 实现逐题轻量存档并返回下一动作，支持短修复和恢复。
- 精简保存参数及响应，保留原始首次评级和必要判定内容。

### 阶段 D：优化开课与文档

- 完善课前预备，组合开课中的确定性步骤。
- 为无复习、有复习、断线恢复和备用材料分别验证路径。
- 同步 skill 和 references，缩短新对话必读内容，消除旧调用示例。

### 阶段 E：课堂验收

- 在相同模型与尽量相同环境下记录优化后体验，区分新对话与已有上下文。
- 对比三个位置的耗时、调用次数和异常长等待。
- 若瓶颈主要剩在平台或模型等待，明确报告，不把脚本通过测试等同于体验已经达标。

## 7. 验收标准

### 正确性必须满足

- 严格队首、到期选择、题型、容量、首次评级及学习证据语义保持不变。
- 反馈先展示，之后存档；普通文本首答到首次实质反馈之间不插入工具、文件读取或联网。
- 每个需要存档的互动完成后至多一次正常保存往返；错误重试沿用原操作编号和相同内容。
- 保存确认后才展示下一项需要作答的任务；保存失败不要求重复回答已经完成的题目。
- 相同请求重试不重复记录、不重复推进；相同操作编号但内容不同应拒绝。
- 主课只有完整契约校验成功才展示；预编译不能绕过运行时保护。
- 课中只写待提交状态，不提前改变正式复习日期、强度或长期结论。
- 正式结课仍依 committed receipt，不通过删除必要保护缩短课堂耗时。

### 性能验收

以下为本方案提出的首轮工程目标，不是已有测试结果，也不是对平台延迟的保证：

| 场景 | 首轮平均值目标 | 对照用户当前报告 |
| --- | ---: | ---: |
| 已有上下文开课 | 不超过 25 秒 | 45 秒 |
| 普通正确回答后的复习题间 | 不超过 15 秒 | 40 秒 |
| 复习转主课 | 不超过 20 秒 | 85 秒 |

每类已有上下文场景尽量收集至少 10 个样本，报告均值、中位数、最大值及样本量；样本不足时明确说明。带互动修复的样本单列，不计用户修复用时。

新对话首次进入单独采样，首轮争取完整首题在 60 秒内出现，并逐次解释超过 120 秒的异常；少量样本只能作初步验证，不能声称长尾已消除。外部延迟仍纳入用户体验记录，同时标明可控与不可控部分。

代码侧目标：复习题间正常路径一次保存即得到下一动作；复习转主课一次组合调用即得到正式主课题；开课恢复和启动减少由 AI 介入的机械往返。实际需要额外调用的例外必须显式说明原因。

## 8. 验证、数据保护与上线

实施前按维护入口读取项目规则，检查并保留用户既有改动。测试使用隔离副本或 fixtures，不拿真实课程开课、提交或重建来做性能实验。

必要测试包括：正确回答前进、错误短修复、漏答、invalid、反馈泄题、题批容量、重复保存、过期修订号、跨题编号误用、响应丢失、保存后准备失败、新对话恢复、缓存未命中及无复习直接进入主课。

若 checkpoint 增加字段，优先采用可兼容读取。旧进行中 session 保持原冻结规则；不在课程中途强行套用新状态。无法兼容时采用明确版本分流及经授权的维护转换，不能静默改写真实草稿。

真实 `learner/`、`sessions/`、`.state/` 不作为本方案文档任务的修改对象。后续实施若确实需要转换这些数据，应单列转换范围与验证方法，不能把流程优化理解为任意迁移历史档案的授权。

新写入格式上线前确认旧代码能否恢复；不能读取时，不允许直接回退旧代码处理新草稿。优先完成当前课程或使用经过验证的兼容恢复路径。

## 9. 完成定义

只有目标路径已经实现、文档与代码一致、隔离测试通过，并完成或明确尚缺真实课堂耗时验收，才能报告实施结果。功能完成与性能目标达成分别报告。

本文件是此次课堂提速的专项方案，与 [学习系统设计](learning-system-plan.md) 中既有设计共同使用；后续实施需同步受影响协议，不能只凭方案文字改变正式教学行为。

## 10. 实施结果（2026-10-01）

### 已落地

1. **组合开课。** `Bootstrap -EnterSession -IdempotencyKey ...` 在一次外部调用中检查、恢复或启动课程，并在条件具备时准备首个主课活动。普通 Bootstrap 保留查询入口；旧进行中 session 不转换。
2. **逐题复习。** 新课使用 `classroom_version=1`。`PrepareReviewQuestions` 在出题前一次冻结选定切片；`SaveReviewAnswer` 只提交当前题的必要结果或修复变化，保存后直接返回下一动作。程序维护题位置、短修复次数及首答评级。
3. **复习直达主课。** 最后一题保存后，在同一个工具调用内绑定主课首活动，并复用 PrepareActivity 校验；中断时恢复主课准备，不重放复习。
4. **课前模板。** 周期发布与正式结课后的预加载尝试生成 `.state/classroom-templates/` 派生缓存，按 package hash、ladder hash 和编译器版本校验。缓存缺失时由已有完整 core 确定性补齐，不让 AI 重新创作整题；特殊 probe 等情形仍保留显式准备分支。
5. **更小的交互内容。** 已冻结契约由程序按题号查找；复习答题调用不重复提交整份题面和契约。返回只带当前题、必要恢复信息及后续目标摘要；后续目标摘要仅供检测泄题，不向学习者提前展示。
6. **教学入口简化。** 按 writing-for-agents 的步骤、完成条件和条件引用方式重写 SKILL.md；增加 classroom-flow.md，把直接教学需要的规则移到 review-teaching.md。排程与维护细节继续保留在 review-protocol.md。
7. **计时与边界。** 每次 tracker 响应附脚本耗时与压缩响应大小，未知的模型及用户等待为 null。题间仍需一次可靠存档；不能把程序内部耗时当作端到端体验。
8. **延期一致性。** 因反馈而暴露的未答目标只保存控制事件，不生成评分或改 due；当日有界延期集合跨结课或明确放弃保留。新接口的判断标签会转换为原排程程序认可的值。

### 验证结果

- V3/V4 回归合计 **71 项通过，0 项失败**；其中新增逐题课堂测试 16 项。
- 覆盖无复习开课、逐题推进、正式结课提交、首答评级保护、短修复与重构、重复请求、过期修订号、错误题号、队首变化、存档后准备中断、材料失效、跳过、invalid、泄题延期和旧 session 恢复。
- 对真实 C0005 课包仅做内存中的只读检查：六节训练课均可生成通过契约校验的主课模板；第七项是轮次复盘，保持独立分支。
- 对真实 `learner/`、`sessions/`、`.state/` 共 **162 个文件**比较修改前后校验值，无新增、删除或内容变化。
- PowerShell 语法与本次文档引用、frontmatter 检查通过。skill-creator 自带 `quick_validate.py` 已尝试，但当前 Python 缺少 PyYAML，未能运行完成；未安装全局依赖，使用独立的结构和链接检查补充验证。
