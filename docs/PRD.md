# English Learning 产品需求文档

版本：0.1 · 核查日期：2026-10-06

面向：没有项目背景的接手维护者与 AI。

本文说明产品为什么存在、需要做到什么，以及当前做到哪里。它不是上课时逐条执行的指令，也不授权改变学习档案或现有计划。**需求描述不等于功能已经实现**；实现状态见第 7 节，具体执行按 skill 与协议。

## 1. 背景与产品定位

项目发起者是一名计算机专业大学生，自述英语水平不理想，一直缺少有效、稳定的提升途径。暑假接触 Codex 后，他希望将其变成自己的专业、个性化、长期英语私教，因此创建了这个项目。

产品是一套在 Codex 对话中运行、使用本地学习档案维持连续性的英语教练系统。学习者提出开始学习等请求，AI 负责备课、教学和解释，程序负责课程顺序、记录、复习排程与恢复。

产品要解决的核心问题是：**学习者不必每次从零解释自己的情况或自行设计课程，也能持续获得适合自己的训练，并知道近期练习与长期进步有什么关系。**

“英语不好”是创始背景中的自我描述，不是系统诊断。当前水平、目标和偏好应读取学习档案，不在 PRD 固定某个等级，也不依据自述替代评估。

### 已确认的方向

- **真实英语能力提升优先。** 听、说、读、写的实际理解与表达能力是主要目标；TOEFL 是应用场景和阶段性检验。有明确考试需求后再讨论备考取舍。
- **当前版本只服务项目发起者。** 面向其他学习者的初始化与独立档案是未来候选，不是近期交付条件。
- **采用能持续使用的个人项目标准。** 为教学效果、课堂连贯性、记录可信度和可维护性服务，不因框架完整性扩大工程范围。
- **维护者需要能够理解并接手。** 文档应说明设计边界与现状，不能要求接手者先读懂所有内部名词。

既有档案中的 B2 方向、考试参考目标和时间计划属于个人学习目标，可随确认调整；它们不是产品保证达到的结果。

## 2. 目标使用者、需求与成功判断

### 2.1 当前使用者

使用者需要有人替自己组织持续训练，能用中文理解困难概念，并通过英文完成主要练习。他具备基础计算机知识，也会参与项目维护，但上课时应能专注学习，不必理解文件结构、事务编号或脚本参数。

当前默认约每次 30 分钟，以六次训练加一次复盘组成一轮，不绑定自然周。具体偏好和计划读取学习档案与配置；这些默认值不是对所有未来学习者的假设。

### 2.2 “专业、个性化、长期”应有的具体行为

| 用户期待 | 产品需要做到的事情 | 判断依据 |
| --- | --- | --- |
| 专业 | 任务目的明确，标准在作答前确定；反馈准确且抓重点；区分训练与独立检查 | 能解释当前练习在练什么、哪里需要改、为什么 |
| 个性化 | 根据可靠表现、目标与偏好选择任务和反馈，关注主要瓶颈，同时维护其他技能 | 调整能指出学习依据，不只是换成感兴趣的话题 |
| 长期 | 保存必要表现，安排延迟复习，跨课程判断目标，保留目标变化与恢复位置 | 换对话或中断后不依靠重新自述维持进度 |
| 可持续 | 开始学习成本低，等待尽量短，反馈不过载；停学后可继续 | 学习者能顺畅完成课程，中断不会制造虚假的落后或失败 |
| 可信 | 说明证据不足、材料不可用和技术失败，不把它们包装成能力结论 | 结论可追溯，保存状态与实际提交一致 |

成功判断以长期可迁移的英语表现为主，同时观察课堂连贯性与使用负担。课程完成次数、练习数量、复习正确率和回答速度可作辅助信息，不能单独证明掌握或等级提升。

不承诺固定期限提分。系统判断与学习者的真实体验需要一起检查；代码测试通过也不能证明每一次教学回复都正确。

## 3. 范围与非目标

### 当前产品范围

- 开始或继续当前课程，按计划推进听说读写训练。
- 独立的到期复习、回答反馈、必要纠错与迁移练习。
- 保存首次表现和实际帮助情况，恢复进行中的教学动作。
- 正式结课、轮次复盘、确认目标与下一轮计划。
- 展示有依据的学习进度及证据局限。
- 完整本地备份与恢复，支持维护者检查并修改项目。

### 当前不承担

- 新学习者即开即用的初始化、多用户账户、商业课程平台或部署服务。
- 官方 CEFR 认证、官方考试成绩、未经核验的分数换算或效果保证。
- 在缺少可靠音频与分析能力时提供发音、重音、节奏、语调评分。
- 自动云同步、自动上传学习档案或跨设备实时协作。
- 通过擅改历史记录、降低既定标准或把辅助回答算成独立成功来制造进步。

真实网络材料和本地原创备用材料都可使用，选择应服从教学适合度、可访问性与权利边界；不要求每节课临时联网寻找新材料。

## 4. 一次完整学习经历

```text
开始／继续学习
  → 找到当前课程或队首课程
  → 有到期复习时逐题作答、反馈
  → 主课任务：独立首答、反馈、必要的同题修复
  → 条件允许时在新题或新情境中检查迁移
  → 展示总结并正式保存
  → 一轮结束后复盘
  → 确认下一目标与计划，发布下一轮
```

| 阶段 | 学习者体验 | 产品必须保证 |
| --- | --- | --- |
| 开始／恢复 | 一句话继续学习，知道眼前要做什么 | 恢复未完成课程；不重复已经完成的首答，不跳过队首 |
| 复习 | 一次一道题，回答后得到简明反馈 | 复习顺序和评级不被主课焦点随意改变；题面不泄露待检验答案 |
| 主课 | 围绕明确目的完成有意义的任务 | 材料、任务要求、允许帮助与判定依据在首答前确定 |
| 纠错 | 明白关键问题，先修改受影响部分 | 首次结果与辅助下的修改分别记录；新迁移任务另行呈现 |
| 结课 | 先看到本课总结，再知道保存结果 | 只有程序确认提交完成，才报告正式保存或课程完成 |
| 复盘 | 了解目标进展、证据和下一步建议 | 区分能力缺口、证据缺口和技术问题；建议与记录对应 |
| 下一轮 | 确认自己理解的目标与课程变化 | 已确认内容可靠保存；新目标不覆盖旧目标历史 |
| 退出／故障 | 可以稍后接着学 | 退出默认保持进行中；只有明确放弃才走放弃流程 |

不是每道题都需要完整纠错循环或迁移。明确正确且没有进一步检查必要时直接前进；复杂纠错服从课程时间与帮助预算。

## 5. 核心产品要求

以下是需要维持或逐步达到的行为要求。精确算法、字段与动作参数由对应协议维护，不在本文件复制。

| 编号 | 要求 | 可观察的验收表现 |
| --- | --- | --- |
| R01 | 课程连续性依赖持久记录 | 新对话恢复到正确课程与等待动作；无需用户再次解释完整历史 |
| R02 | 独立作答前保护答案 | 改错题只展示任务和错误版本；评分答案在作答后用于反馈，不与题目一并给出 |
| R03 | 复习支持表达不确定 | 每批开始说明可以在答案后加 `?`；不会仅凭消息间隔猜测思考时间 |
| R04 | 反馈及时且有限 | 回答后先给实质反馈，再保存；不为普通回答插入额外搜索或多轮模型复核；优先处理少量高价值问题 |
| R05 | 首答与修复分开 | 同题修改不覆盖首次判断，不增加独立证据；记录实际帮助，答对后不清零 |
| R06 | 个性化有依据 | 目标、任务与难度建议能解释依据；关注瓶颈的同时保留听说读写覆盖 |
| R07 | 原子复习独立 | 单词、表达等到期复习保持独立排程；主课目标完成不等于这些项目掌握，反之亦然 |
| R08 | 长期结论诚实 | 单次正确、被提示后修好、课程数增加均不自动成为长期达标；证据不足明确说明 |
| R09 | 计划确认有意义 | 只有实质不同的方案才给备选，并说明选择会改变什么；只有一个有依据的方案时直接推荐并征求确认 |
| R10 | 保存和恢复可信 | 重试不重复计入事实；失败不报告已完成；中断后目标、计划与学习记录保持一致 |
| R11 | 材料与模态真实 | 有可用音频才按听力条件检验；文字转写不能冒充声音分析；材料不可用时透明降级 |
| R12 | 记录适量且可追溯 | 保留解释判断和恢复所需的片段与引用；不默认保存完整私密对话、无关信息或完整录音 |
| R13 | 学习数据可恢复 | 备份包括必要运行状态与匹配代码；恢复先校验并写入新目录，不覆盖现有项目 |

### 教练与学习者的职责

教练负责提出有依据的任务、反馈、候选结论和计划。学习者负责实际作答、表达需求，并确认新的目标及实质计划变化。已经确认的选择应沿用，避免反复询问。

学习者可以质疑评分；系统应核查依据并走相应更正流程。对客观记录的更正与对下一轮计划的个人偏好，是不同的操作。

### 进度判断的层次

需要分清：本次任务是否完成、某个表达是否保持、局部目标是否达成，以及整体技能等级是否稳定。它们可以互相提供线索，但不能自动等同或逐层升级。

例如“提示后改好了这个句子”说明这次教学可能有效，不足以证明学习者下次能独立使用；“一个口语目标完成”也不等于整个口语等级提升。

## 6. 体验与性能要求

核心诉求是维持课堂连贯感。优先关注完整首题出现、首段实质反馈出现、下一题出现和复习转主课的等待；结课保存也应可靠并说明状态，但不能为了缩短等待跳过正确性检查。

采用已有专项方案中的工程目标，不把它们写成已达成的承诺：

| 场景 | 已有目标 | 验收状态 |
| --- | --- | --- |
| 已有上下文开课 | 平均不超过 25 秒 | 待可比的实际课堂计时验收 |
| 普通正确回答后的复习题间 | 平均不超过 15 秒 | 同上 |
| 复习转主课 | 平均不超过 20 秒 | 同上 |
| 新对话首次进入 | 单独采样；完整首题争取 60 秒内出现 | 波动单独记录，不混入已有上下文样本 |

计时边界、历史基线与异常记录方式见 [课堂提速方案](design/classroom-latency-plan.md)。脚本内部耗时不等于学习者等待时间；无法测得的部分标为未知。

截至 2026-10-06，用户定性反馈整体运行时间缩短，结课改善最明显；没有足够新数据证明上述数值目标已经达成。用户还报告同期模型服务提速，贡献不能拆分，也不能据此解释质量波动。

教学质量与速度分别验收：既要检查保存与恢复，也要检查真实输出有没有泄题、漏提醒、无效选项。一般不通过增加课中模型调用来修复简单展示问题。

本节是截至核查日期的快照，后续变化需更新。标为“已实现”表示存在执行路径与相应验证依据，不表示不存在缺陷，也不表示已证明长期教学效果。

| 能力 | 状态 | 当前边界与依据 |
| --- | --- | --- |
| 开课、队列与恢复 | 已实现 | 从已有学习实例开始或恢复；见 [课堂流程](../.agents/skills/english-coach/references/classroom-flow.md) |
| 逐题复习、反馈后存档及转主课 | 已实现，有体验缺陷 | 漏 `?` 提醒与答案泄露已由实际使用报告；不是当前可忽略的边界情况 |
| 主课同题修复与恢复 | 已实现 | 保留首次判断、后续变化、帮助情况；见 [教学微循环](../.agents/skills/english-coach/references/teaching-loop.md) |
| 正式结课与重复请求处理 | 已实现 | pending 草稿到 committed 正式提交；见 [运行协议](../.agents/skills/english-coach/references/runtime-protocol-v4.md) |
| 跨轮局部目标判断 | 实用版已实现 | 读取同一目标最近最多四个完成轮次，输出达标／继续／重设／证据不足；见 [目标复盘](../.agents/skills/english-coach/references/goal-review.md) |
| 确认后的目标换版与下一轮发布 | 已实现 | 旧历史保留，支持中断恢复；见 [轮次发布](../.agents/skills/english-coach/references/cycle-publication.md) |
| 复盘建议的可选择性 | 有体验缺陷，待修改 | 已出现没有讲清实质区别的备选方案；取消强制备选尚未实施 |
| 完整分技能等级与阶段升级 | 未完整接通 | 普通复盘不能从局部目标结论自动得到 competency/stage 升级；见 [长期状态](../.agents/skills/english-coach/references/long-term-state.md) |
| 更完整的进步与教学洞察判断 | 部分实现／待扩展 | 已有保守的标准习得判断；减少帮助后的进步、情境类别迁移、完整 insight 流程仍待扩展 |
| 更正／作废后的长期重算 | 待扩展 | 相关记录可能进入待审计状态，不自动重放后宣告达标 |
| 跨日复习名单刷新 | 已知缺口，主动暂缓 | 用户明确暂不修复；新日期可能沿用旧缓存，不能宣称每日到期名单始终准确 |
| 听力材料与口语评估 | 有材料，依赖宿主能力 | 已有本地原创听力音频与 transcript；完整实时语音测评不是已实现能力 |
| 完整备份与恢复 | 已实现，手动触发 | 包括 `.state` 与当前代码；不等于自动备份或云同步；见 [备份说明](../maintenance/backup-guide.md) |
| 他人初始化 | 未实现，未来候选 | 目前不能承诺克隆项目后即可供另一人独立使用 |

**当前实例已完成结构化目标换版。** 2026-10-06 只读核查确认存在 active 的结构化目标版本；不要继续沿用较早文档中“下一次才升级旧文字目标”的状态说明。PRD 不复制当前目标 ID、私人表现或成绩，具体值始终查询学习档案。

## 8. 近期重点与后续候选

### 已登记的近期问题

按风险优先处理出题泄露答案，再处理复习开场提醒和复盘备选。具体原文、假设、修改范围及验收方式统一放在 [课堂可靠性待修改清单](design/classroom-reliability-followups.md)，不在本文件维护第二份完整方案。

同时用正常课程与复盘检验已实现流程是否好用，记录实际等待时间和教学体验。全部在同一长对话中使用是已知背景；上下文压缩或模型服务变化是待核实因素，不当作已确认根因。

### 后续候选，不构成当前承诺

- 完整能力等级与阶段判断，以及更多进步标记和教学洞察。
- 更正、作废记录的自动重算与更完善的审计体验。
- 常用个性化偏好的清晰入口；README 如何面向发起者提供小修改指引另行讨论。
- 面向其他学习者的初始化、独立档案与上手流程。

跨日复习刷新维持暂缓决定，除非用户重新提出。新增功能先说明它改善了哪种实际学习体验，避免仅因为设计文档里出现过就默认实施。

## 9. 数据、运行与维护边界

当前实现以本地文件为基础，由 PowerShell tracker 管理状态。AI 的自然语言教学和程序的确定性记录是互相配合的职责；把某项行为写进 skill，并不意味着程序已经强制保证它。

- `learner/`、`sessions/`、`.state/` 都按真实学习数据保护。`.state` 包含必要恢复状态，不可整体当成可随意丢弃的缓存。
- 课中 checkpoint 是恢复所需草稿；正式事件与 committed receipt 是保存完成的依据。
- 目标标准的新版本从确认后的新轮次开始生效；旧证据缺失的条件不能追溯补造。
- 外部材料须满足可访问性与权利边界。考试时效信息另做有日期的官方核验，不在 PRD 固定易过时的题型或分数转换。
- 无可靠录音与声音分析时，只对能观察到的表现反馈；音频缺失不使用文字练习冒充听力测评。
- 普通上课不执行迁移、全量维护、测试或代码修改。维护与学习记录分别验证。

项目当前运行使用 v4；v3 协议与样例保留供历史审计和兼容，不应仅为缩短阅读而删除。具体维护要求见 [MAINTENANCE.md](../MAINTENANCE.md)。

## 10. 验收与接手阅读路线

### 如何判断改动完成

1. 受影响的用户行为满足对应要求，并说明已知限制。
2. 保存、恢复、排程或目标逻辑变更在隔离数据中进行相称验证，不拿真实学习档案做实验。
3. 展示与教学规则变更检查真实风格的回复样例，包括正常回答、错误、模糊回答、答案暴露、恢复和复盘建议等相关分支。
4. 性能报告区分端到端体验与脚本指标，说明采样条件；没有测量就不宣称达标。
5. 产品行为改变时更新对应规则与本文件的状态；仅实现细节变化无需在 PRD 重复记录。

本次编写只读核查实现、文档与已有测试内容，没有重新运行测试，不把历史通过数量当成本次运行结果。
